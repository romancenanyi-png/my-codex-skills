# 07｜询盘、统计与运营

## 一、询盘表单越短越好，但要够用

首屏表单可保留：

- 姓名；
- 公司；
- 企业邮箱；
- WhatsApp（选填）；
- 项目留言。

数量、目标价格、材料、Logo 工艺、交期和运输信息可以在留言提示或后续回复中补齐。字段多少要用真实完成率和线索质量验证，不能只凭感觉。

## 二、投递链路验收

```text
用户点击提交
  → 浏览器校验
  → 提交服务/后端接受
  → 企业邮箱收到
  → 销售及时回复
  → 需求确认/报价/打样/订单
```

每一层都可能失败。前端不能在实际失败时显示成功；免费邮件转发服务也不能保证主收件箱投递。

## 三、询盘台账

| 字段 | 用途 |
| --- | --- |
| 日期、唯一编号、是否测试 | 排除测试、重复和垃圾信息 |
| 来源、首次页、提交页、UTM | 判断渠道；缺失就写未知 |
| 国家、公司、买家角色 | 判断 ICP 匹配 |
| 产品、数量、定制、交期 | 判断是否可做 |
| 阶段 | 新询盘、已回复、确认、报价、打样、订单、失联 |
| 首次回复时间 | 改善响应速度 |
| 未继续原因 | 反向改善页面、报价和资格筛选 |

## 四、不要算错转化率

同一个转化率必须使用同一时间段、同一渠道和同一人群。例如：

```text
有效询盘转化率 = 同期有效询盘数 ÷ 同期可识别网站会话数
```

不能拿历史累计询盘除以某几天的 GSC 点击。表单点击、平台接收、邮箱收到、有效询盘和订单也不能混为一个事件。

## 五、每周运营闭环

1. 本周哪些页面或表单发生变化；
2. 部署是否对应目标 commit；
3. Google 实际发现、抓取、索引和展示了什么；
4. 询盘来自哪里、是否有效；
5. 买家反复问什么；
6. 下周只做一个最有证据的改进。

## 六、统计和隐私

统计工具上线前要定义事件、隐私说明和数据保留范围。邮件点击或 WhatsApp 点击是意向信号，不等于消息送达或成交。公开仓库只存字段设计和方法，不存真实客户数据。
