# 09｜提示词与检查表

## A. 新站规划提示词

```text
使用 $b2b-website-architecture，先读取我提供的业务资料。

请为 [行业/产品] 的 [目标市场] B2B 买家规划网站。
主要转化：[询价/预约演示/样品申请]。
已确认事实：[列出]。
未知或不能公开：[列出]。

输出：
1. 买家与采购路径；
2. 分阶段 sitemap；
3. URL、搜索意图、证据和 CTA 表；
4. 导航、面包屑和内链；
5. Phase 1 最小上线范围；
6. 需要我补充的资料。

不要写页面代码，不要虚构业务数据。
```

## B. 页面实施提示词

```text
先读取项目规则、现有代码、指定资料和当前 Git 状态。

目标：实现/修改 [URL 或模块]。
范围：只改 [文件/组件]。
事实来源：[文件或已确认答案]。
保留：[URL、设计系统、表单、SEO 策略]。
禁止：[无关重构、虚构证据、自动部署、提交密钥]。

实施前说明现状和方案；实施后运行构建、测试，检查
390 / 768 / 1440，无溢出、坏图、死链或表单回归。
列出修改文件、验证证据和未解决风险。
```

## C. SEO / GEO 诊断提示词

```text
使用 $b2b-seo-geo-ops 对 [网站/页面] 做只读诊断。

区分：已发布、可抓取、可索引、已索引、排名、点击和询盘。
逐 URL 检查状态码、robots、noindex、canonical、title、H1、
可见回答、内链、Schema 与 sitemap。
把平台数据、SERP 观察、AI 建议和推断分开。

输出按影响/工作量排序的问题、证据、建议和验证方式。
本轮不要改代码、请求收录、部署或提交测试表单。
```

## D. 部署提示词

```text
在我明确授权的范围内发布当前变更。

开始前检查 git status、分支、remote 和 diff。
运行生产构建与现有测试；只提交本次相关文件。
推送后确认 Vercel Production 对应目标 commit。
检查正式域名页面、图片、表单、canonical、robots 和 sitemap。

分别报告：
- 本地验证；
- GitHub commit；
- Vercel 部署；
- 正式域名验证；
- 尚不能证明的搜索/经营结果。
```

## E. 询盘测试提示词

```text
先做只读检查并说明实际提交链路。
只有得到我的测试授权后，提交一条带唯一 TEST 编号的询盘。
验证浏览器响应、提交服务接受和企业邮箱最终收件。
测试数据不得计入真实询盘，不得公开邮箱、令牌或内容。
```

## F. 最终交付清单

- [ ] 源资料与公开内容已脱敏；
- [ ] 页面地图和关键词归属完成；
- [ ] 重点页面内容与真实证据一致；
- [ ] 表单和企业邮箱完整验收；
- [ ] GitHub 版本可回滚；
- [ ] Vercel 与正式域名已验证；
- [ ] Search Console 与统计已建立基线；
- [ ] 90 天运营计划有负责人和复盘日期；
- [ ] 没有排名、收录、AI 引用或询盘保证。
