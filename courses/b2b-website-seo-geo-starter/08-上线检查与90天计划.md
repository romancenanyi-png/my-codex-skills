# 08｜上线检查与 90 天计划

## 上线前

### 业务与内容

- [ ] 公司定位、产品、市场与 CTA 清楚；
- [ ] MOQ、周期、认证、产能和案例均有证据；
- [ ] 未确认事实没有补猜；
- [ ] 页面不是竞争对手文案换品牌名。

### 页面与技术

- [ ] 首页、类别、能力、About、Contact、指南和隐私页可访问；
- [ ] 无明显 404、坏图、死链接和横向溢出；
- [ ] 390 / 768 / 1440 宽度通过；
- [ ] Title、description、H1、canonical、robots 正确；
- [ ] sitemap 只含希望索引的 200 规范 URL；
- [ ] 结构化数据与可见内容一致；
- [ ] 表单成功、失败、企业邮箱收件均测试；
- [ ] 密钥、个人信息和原始客户资料未进入 GitHub。

### 发布

- [ ] 生产构建和测试通过；
- [ ] Git diff 只包含本次范围；
- [ ] GitHub commit 可追溯；
- [ ] Vercel Production 对应目标 commit；
- [ ] 正式域名、HTTPS 和主域跳转正确；
- [ ] 保存上线记录和回滚点。

## 0—14 天：稳定

- 验证域名、Search Console、sitemap 和重点 URL；
- 检查表单投递、垃圾邮箱和回复流程；
- 修复真实技术错误，不为“全部变绿”改正确重定向；
- 建立基线：重点页、查询、展示、点击、询盘、速度。

## 15—30 天：内容与内链

- 优先完善 3—5 个重点产品/类别页；
- 从真实买家问题完成 MOQ、打样、材料、质量等指南；
- 用产品—能力—指南—询盘形成内链；
- 更新有实质变化页面的 `lastmod`。

## 31—60 天：证据和分发

- 增加真实规格、流程、测试和案例边界；
- 在合适的合作伙伴、行业目录和社媒传播；
- 检查 Search Console 的非品牌查询和重点页；
- 检查有效询盘，而不只看流量。

## 61—90 天：同口径复盘

- 对比相同长度时间窗口；
- 分开品牌词与非品牌词；
- 记录 keep / update / merge / create / noindex 决策；
- 根据询盘质量改页面和资格筛选；
- 没有证据的问题保持不动。

## 停止条件

出现以下任一情况，停止继续部署并先诊断：

- 表单无法投递或虚假成功；
- 关键页面、导航或统计回归；
- 正式域名不是目标提交；
- 大量 URL、canonical 或 robots 意外变化；
- 任务需要新的账号权限、预算、外联或发布授权；
- 资料存在明显矛盾或可能构成虚假宣传。
