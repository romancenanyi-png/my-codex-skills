# 06｜GEO 与内容架构

## 一、GEO 是什么

这里的 GEO 指生成式搜索/AI 回答中的可理解性和潜在引用，不是 Google Maps 地图优化。

Google 对 AI 搜索功能的公开说明强调：常规 SEO 基础仍然适用，没有额外的专用技术门槛，也不需要所谓特殊 AI 文件或特殊 Schema。页面必须可抓取、可索引、可显示摘要，但这些条件不保证被 AI 展示或引用。

## 二、B2B 网站应该让机器读懂什么

- 公司是谁、在哪、服务什么市场；
- 供应什么产品，适合哪些买家和场景；
- 能做什么定制，不能做什么；
- MOQ、打样、交期、报价需要哪些输入；
- 生产、质量和交付流程；
- 证书、测试、图片、人员和日期的真实范围；
- 买家下一步应联系谁、提供什么。

## 三、内容集群

```text
商业页面：custom / OEM / private label / wholesale / manufacturer
  ↕
产品页面：产品类别、用途、材料、定制、采购条件
  ↕
知识页面：MOQ、打样、材料、质量、交期、报价准备
  ↕
证明页面：工厂、流程、测试、证书、案例、团队
  → 询盘页面
```

一个关键词主题只指定一个主要 URL。先更新已有高潜力页面，再创建新页面，避免多个页面争抢同一意图。

## 四、直接回答模板

```text
问题：[买家真实问题]

直接回答：[1—3 句，先给结论]
适用条件：[产品、数量、材料、市场]
不适用情况：[边界]
流程：[步骤]
证据：[真实规格、测试、照片、负责人或日期]
下一步：[买家需要提供的信息]
```

FAQ 和 Schema 必须与页面可见内容一致。Schema 只能描述事实，不能创造事实，也不保证富结果。

## 五、关键词数据分层

| 类型 | 可以怎么用 |
| --- | --- |
| SERP 实际结果 | 看页面类型、标题、常见问题与搜索意图 |
| Keyword Planner | 在有账号/API 时记录真实范围、竞争和日期 |
| 第三方问题数据 | 作为问题发现来源，记录工具和限制 |
| AI 建议词 | 只作为候选，不能冒充搜索量 |

没有搜索量时写 `unknown` 或 `null`，不要写 0。不要为凑固定数量捏造竞争对手、H1 或问题数据。

## 六、可信内容标准

- 用公司真实经验写，不抄竞争对手；
- 条件化表达 MOQ、周期和能力；
- 认证过期、范围未知或续证中要写清楚；
- AI 生成图不冒充真实生产证据；
- 作者、更新时间和复核人真实；
- 引用可信来源并保留观察日期；
- 不承诺排名、收录或 AI 引用。
