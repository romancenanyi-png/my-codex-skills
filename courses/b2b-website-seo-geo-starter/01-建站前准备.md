# 01｜建站前准备

## 一、先想清楚网站要完成什么

外贸 B2B 网站的主要目标通常不是在线零售，而是让合适的买家：

1. 看懂你供应什么；
2. 判断你是否适合他的项目；
3. 看到可信证据；
4. 愿意提交需求或联系销售。

把主要转化动作限定为一个，例如 `Request a Quote`。邮箱、WhatsApp、下载资料可以是辅助动作。

## 二、业务资料清单

| 类别 | 必填内容 | 常见错误 |
| --- | --- | --- |
| 公司 | 名称、地点、业务模式、服务市场 | 用空泛口号代替定位 |
| 买家 | 品牌商、进口商、经销商、礼品公司等 | 同时面向所有人 |
| 产品 | 类别、材料、工艺、应用、定制范围 | 只放图片，不说明采购条件 |
| 交易 | MOQ、打样、交期、报价所需字段 | 未确认就写死数字 |
| 证据 | 工厂、流程、检测、证书、团队、案例 | 把 AI 图当真实工厂证据 |
| 联系 | 企业邮箱、电话、WhatsApp、地址 | 表单能点但收不到邮件 |
| 品牌 | Logo、色彩、字体、语气、参考网站 | 直接复制竞争对手内容 |

资料不完整时写 `待确认`，不要让 AI 补猜。

## 三、账号与工具

- 域名注册商账号；
- GitHub 账号和代码仓库；
- Vercel 账号并连接 GitHub；
- Google Search Console；
- 统计工具和隐私说明；
- 企业邮箱或可靠的表单投递服务；
- Codex 与本地项目目录。

账号密码、Cookie、API Key、邮箱激活链接、客户名单和询盘正文不得提交到公开 GitHub。环境变量放在部署平台或本地 `.env`，并用 `.gitignore` 排除。

## 四、项目目录建议

```text
project/
├── AGENTS.md              # 业务事实、限制、验收规则
├── package.json           # 框架、命令和依赖
├── app/ 或 src/           # 页面与组件
├── public/                # 网站使用的优化后素材
├── docs/
│   ├── brief.md           # 公司与项目简报
│   ├── content-map.md     # 页面和关键词归属
│   └── launch-log.md      # 上线与核验记录
└── .env.example           # 只写变量名，不写密钥
```

原始照片、合同、客户数据和证书原件应放在受控资料区，不要全部公开进网站仓库。

## 五、开工门槛

只有下面问题都能回答，才进入建站：

- 网站为谁服务？
- 核心产品是什么？
- 买家最担心什么？
- 能拿出什么证据？
- 最主要的 CTA 是什么？
- 哪些数据已确认，哪些不能公开？
- 谁拥有域名、GitHub、Vercel 和邮箱？
